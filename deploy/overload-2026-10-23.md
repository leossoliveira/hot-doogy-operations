# Post-save overload investigation — 2026-10-23

## Observations

Read-only production diagnostics on project `kfnsfnytnnpwptklmbip` found 217 timeouts in `workspace_read_batch` and 48 across two `workspace_sales_page` query shapes in the preceding 24-hour log window. API logs independently showed 208 batch errors and 20 sales-page errors; these are different log streams and must not be added together.

The database held approximately 16,050 sales facts and occupied 152 MB. At sampling time there were 18 idle client connections and no blocking wait. An authenticated first-page RPC, using an existing authorized session's claims in a rolled-back transaction with an 8-second timeout, completed in 293 ms. This quiet-period measurement is not a load benchmark.

Database statistics reported 118,263 temporary files and 357 GB cumulatively written since August 25. This is historical I/O, not current disk occupancy or proof of current RAM exhaustion. The screenshot reported 74% RAM on Nano compute. Live VPS memory could not be measured: configured SSH identities failed authentication and automatic review rejected trying another identity. No remote configuration, data, schema, or deployment was changed.

## Corrected mechanisms

- A successful write previously discarded the reference to an ongoing full workspace read, allowing the next refresh to overlap it. Invalidations now retain the pending operation and coalesce waiters into one read of the latest generation. Results remain session scoped, with live authorization and no persistent data cache.
- Global and per-workspace bulk read concurrency is two instead of eight. Pending global work is capped at 128 and work older than 15 seconds is rejected before execution. Heavy calculation pages remain exclusive.
- A transient workspace failure has a 30-second cooldown per session. Browser automatic refreshes honor a minimum interval and back off up to five minutes after failures.
- Confirmed-save refresh notifications coalesce and yield 100 ms so the form can close before refresh starts. Manual saves are not delayed by that refresh. Handover saves no longer await reload or reopen the saved occurrence automatically.

## Validation and release

475 Node tests passed. Syntax checks and historical migration integrity checks passed. Eight browser scenarios passed while post-save list responses were deliberately held: order edit/create, invoice payment/approval, inventory completion, HR, My Day, and handover occurrence. Separate browser tests verified supplier edit/create, exact replay after unknown save outcome, immediate closure, preservation of a new edit during a late refresh, and navigation. All browser API responses were synthetic; the local server's Supabase URL pointed to a disabled loopback endpoint.

Release requires explicit GitHub publication authorization under `AGENTS.md`. No database migration is needed. After deployment, validate representative saves under normal concurrent use, compare timeout/error rates and request latency over matching windows, and inspect actual RAM/CPU/I/O metrics before deciding on compute changes. These local tests do not establish a permanent production resolution. Rollback is the preceding application release; no database rollback is required.

Publication adaptation: the current GitHub main does not contain the local handover module. Its UI-only correction and browser scenario are excluded from this release; all seven currently published form scenarios remain covered. The local c7ece18 commit retains that work.
